ACTION SHAPES
Decision 01

基类更快，
接口更轻。Base class for speed.
Interface for control.

两种方式都只依赖公开的 WorkflowRuntime.ActionSdk，不引用 WorkflowCore、Runtime Application 或 Designer。Both modes depend only on public WorkflowRuntime.ActionSdk, never on WorkflowCore, Runtime Application, or the Designer.

RECOMMENDED FOR MOST ACTIONS

WorkflowActionBase

[WorkflowAction(...)]
public sealed class GreetingAction
    : WorkflowActionBase

自动发现 metadata、普通属性、输入和输出。适合大多数业务 Action。Automatically discovers metadata, properties, inputs, and outputs. Best for most business Actions.

MINIMAL EXECUTION CONTRACT

IWorkflowActionHandler

public sealed class PingActionHandler
    : IWorkflowActionHandler

插件注册时提供完整定义。适合零参数或自行管理描述的 Action。The plugin supplies the definition during registration. Useful for zero-parameter or manually described Actions.

判断原则：先从基类开始；只有明确需要时才直接实作接口。Rule of thumb: start with the base class; use the interface when the trade-off is deliberate.

Contributor checklist

扩展完成的标准，
是可被下一个人重现。An extension is complete
when the next person can reproduce it.

保持依赖最小、契约公开、部署可重复，并用现有样例与测试证明行为。Keep dependencies minimal, contracts public, deployment repeatable, and behavior demonstrated by samples and tests.

01

Reference only the required SDK

WorkflowRuntime.ActionSdk for Runtime Actions; WorkflowDesigner.WpfSdk for optional Designer UI.

02

Keep stable IDs and keys

ActionId、ActionType 与 editor key 应由插件拥有并保持稳定。Action IDs, types, and editor keys are plugin-owned and stable.

03

Build into the plugin directory

示例 csproj 已展示本地部署 Target。The sample csproj demonstrates a local deployment target.

04

Restart and inspect the catalog

Verify the Action through the runtime Action catalog before opening the Designer.

05

Test the generic panel first

确认基础体验後，再测试可选的 WPF 扩展。Validate the generic experience before optional WPF extensions.

06

Document the public contract

提供最小示例、部署位置及验证方式。Provide a minimal sample, deployment location, and verification path.

ONBOARDING · ACCESS FIRST
Before the first restore

先授权，再生成 Token。
两边缺一不可。Grant access, then create a token.
Both sides are required.

仓库邀请只解决源码访问；私有 NuGet 包还需要包级 Read 权限和开发者自己的 PAT (classic)。The repository invitation covers source access. Private NuGet restore also requires package Read access and the developer's own PAT (classic).

REPOSITORY OWNER · ONCE

你负责授权Owner grants access

  1. 邀请开发者进入 WorkflowDesigner，并确认对方已接受。Invite the developer to WorkflowDesigner and confirm acceptance.
  2. 在每个私有 Workflow 包的 Manage access 中授予同一账号 Read。Grant the same account Read under every private Workflow package's Manage access.
  3. 不要共享你的 Token。Never share the owner's token.
INVITED DEVELOPER · OWN MACHINE

开发者负责凭据Developer owns credentials

  1. 生成 PAT (classic)，只授予 read:packages。Create a PAT (classic) with read:packages.
  2. 组织启用 SSO 时，为 Token 授权 SSO。Authorize SSO when the organization requires it.
  3. 运行 .\bootstrap.ps1 -ConfigurePackages。Run .\bootstrap.ps1 -ConfigurePackages.
